Pipeline Architecture · v2.1

An eleven-agent pipeline for macro data,
designed to verify itself.

Three external data sources, six deterministic Python agents, three Claude-driven agents, two off-cycle workers, and a nine-pass validator that doubles as the build gate.

Cadence Saturday 12:00 UTC · monthly 2nd Sat 14:00 UTC Runtime ~4 minutes Quality checks 480+ per run

All systems nominal. Last run 1cfa23d passed 462 of 477 checks (3 critical, 12 warnings) two minutes ago. Next scheduled run in 5d 8h.

01Overview

Each agent has a single, narrow responsibility and reads only the artefacts produced by the agents preceding it. None of the AI agents touch raw data; none of the deterministic agents touch model output. Failures at any stage are surfaced by the validator and gated by the publisher — nothing reaches GitHub Pages or the briefing email until the validator returns PASS.

The architecture is now designed so that the same bug class — a rebuild silently failing while a stale seed continues to ship — can never recur. Every external dependency is pre-flight validated, every renderer key is statically contracted against the collector, and every static seed is recomputed from raw data on every run. — docs/SELF_VERIFICATION.md, May 2026 audit

02The agents

Agent 0 · Pre-flight preflight.py

healthylast run 36sp95 38s

Validates external dependencies before the pipeline runs. Extracts every FRED series_id literal from the collector source and pings each one with limit=1. Verifies every Claude model ID in scripts/_models.py against Anthropic's /v1/models catalog. Halts the pipeline immediately on any 4xx so downstream agents never run on broken dependencies.

Agent 1 · Collector collector.py

healthylast run 21s79 series

Pulls all 79 macro series via public APIs — daily yields and credit spreads, weekly mortgage and gasoline, monthly inflation and labor, quarterly GDP. Retries 429 and 5xx with exponential backoff. Carries forward the prior snapshot's value when a series transiently fails so a one-off network blip never blanks a chart.

Agent 2 · Analyzer analyzer.py

healthylast run 1s

Diffs the current snapshot against the previous run. Scores threshold-crossing signal changes (CPI moving more than 0.1pp, IG OAS moving more than 3bp, etc.) and emits a list of headlines. The output is what tells Agent 3 which tabs need fresh commentary.

Agent 3 · Analyst claude-sonnet-4-6

healthylast run 7s4096 max_tokens

Smart refresh — only regenerates commentary for tabs whose underlying data has moved past noise threshold. Returns structured JSON with risk posture, macro regime, KPI updates, and per-tab analysis. On parse failure carries forward the prior run's commentary instead of blanking it.

Agent 4 · Renderer renderer.py

healthylast run 12s

Regex-based HTML patcher. Rebuilds chart constants, KPI strip values, panel titles, and AI commentary blocks directly into index.html. The renderer is the source of truth for what each chart shows; the static seeds in HTML exist only as fallbacks for when the rebuild fails. Pass 3g now verifies that fallback path can never silently take over.

Agent 6 · Validator validator.py · build gate

healthylast run 38s462 checks

The build gate. Runs nine independent passes (full table below), aggregates findings into data/validation_report.json, and exits non-zero if any critical divergence is found — which halts the publisher before the dashboard can ship with bad data.

Agent 5 · Publisher publisher.py

healthylast run 7s

Commits the rendered index.html to main, deploys to GitHub Pages, and sends the weekly briefing email via Resend. A post-deploy healthcheck verifies the live page; auto-rollback restores the last known-good snapshot if the page fails to load.

Agent 7 · Visual QA visual_qa.py · 295 DOM checks

healthylast run 22s

Headless Chromium walks every tab. Verifies JS executes without errors, charts render to non-zero canvas dimensions, KPI tiles contain real numbers rather than placeholders. Captures screenshots that Agent 8 then analyses.

Agent 8 · Vision Review claude-sonnet-4-6 · vision

healthyper-tab screenshot analysis

Sends each tab screenshot to Claude's vision API for pixel-level defect detection — broken chart lines, overlapping axis labels, blank panels. Catches the visual bugs that pure DOM checks miss.

Agent 9 · Earnings claude-sonnet-4-6

quarterly · own cronnext: Jul 10

Autonomous quarterly bank earnings pipeline. Runs on its own cron during earnings weeks, fetches each bank's transcript, has Claude extract eight verbatim fields under a strict no-paraphrase schema, and gates the result through validator Pass 3c. Never touches the weekly cadence.

Agent 10 · Repair Agent repair_agent.py · observer v1

observer mode3-week observation window

Reads the validation report after every pipeline run and surfaces accumulated drift into a structured rolling log. Currently passive — no automated fixes. Per project policy, observer mode runs for at least three weeks before any fix-writing logic is shipped, so the trigger signal can be evaluated before the agent acts on it.

Pipeline runtime

Of the eleven agents, only three call an LLM (Agents 3, 8, 9). The remaining eight are pure Python with no inference cost. Each agent is independently testable and independently failable — a Claude outage degrades commentary freshness but the dashboard still ships with carry-forward content; a FRED outage halts at Agent 0 with a clear actionable error rather than silently producing wrong charts.
