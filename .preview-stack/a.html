How the Dashboard Works

An eleven-agent pipeline that turns public macro data into a weekly CEO briefing.

Every Friday, Python agents pull from FRED, BLS, EIA, UMich, and earnings transcripts, score the signals, draft commentary, render the page, and gate publication on a ten-pass validator. Claude writes the prose; the structure is deterministic.

What it does

§ 01
Pulls weekly

FRED, BLS, EIA, UMich, plus quarterly earnings transcripts. Single weekly cycle Fri morning.

Scores the signals

Compares each metric against the playbook's noise floor and known-normal bands. Flags divergences.

Writes the briefing

Claude Sonnet drafts 2–4 sentence commentary per tab, constrained by §2 copy rules. No numerics outside the KPI tiles.

Guardrails

§ 03 · technical detail
AGENT_DISABLE_ALL

Hard kill-switch. Stops every agentic LLM call regardless of other flags.

AGENT_MAX_LLM_CALLS

Per-run cost cap. Bounded budget across the four LLM agents.

PATH ALLOWLIST

Each agent has a strict allowlist of writable paths. Layout and renderer are never on it.

AUDIT LOG

Every LLM call appends to data/agent_memory.jsonl (rolling cap 2000).

Sources of truth

§ 04
Visual contract

data/style_guide.md codifies layout, typography, palette, spacing, and cross-tab consistency rules. Agents 7 and 8 enforce against it.

Data contract

data/playbook.md + data/known_normal.json define what counts as normal. Validator passes 1–3h enforce.

Editorial contract

Briefing prose is bounded by §2 of the playbook: 2–4 sentences, no hedging, every numeric matches the corresponding KPI tile.
